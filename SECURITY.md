# Security Policy

## Supported Versions

| Version | Supported |
| --- | --- |
| `0.2.x` | Yes |
| `< 0.2.0` | No |

## Reporting a Vulnerability

Please do not report security vulnerabilities in public issues, pull requests, or discussions.

Use the most private channel available to the repository you are working with:

- If the canonical upstream repository has GitHub private vulnerability reporting enabled, use that.
- If you are working from a fork or mirror without private reporting, contact the repository owner or maintainers privately before disclosing details.

When you report an issue, include:

- the affected component and version
- deployment mode or settlement mode, if relevant
- reproduction steps or a proof of concept
- impact and expected blast radius
- suggested mitigations, if you already have them

We aim to acknowledge reports within 5 business days, coordinate a fix privately, and publish a changelog entry once a remediation is available.

## Disclosure Expectations

- Give maintainers reasonable time to investigate and ship a fix before public disclosure.
- Avoid posting exploit details publicly while users are still exposed.
- Once a fix is shipped, we encourage a coordinated public write-up so downstream integrators can patch quickly.
